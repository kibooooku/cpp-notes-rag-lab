## 一、标题与研究问题

建议标题：**基于个人 C++ 笔记的 RAG 问答助手：BM25 与向量检索对照实验**。

研究问题：在同一份 C++ 个人笔记、同一套切分与生成配置下，两种检索方法在概念解释、机制说明、适用条件、语义改写、跨章节关联和资料无答案问题上有何差异？文件、章节和行号引用能否帮助核查回答？系统如何处理缺证据、部分证据及资料本身存在歧义的情况？

两组都是 RAG：先检索，再由 DeepSeek-flash 基于证据回答。主要对照变量是 BM25 关键词检索与 BGE + Chroma 向量检索。所有结论限定于本次语料、20 道题及实际运行条件。

## 三、第 1 页：系统、资料与实现

### 1. 任务与使用范围

说明系统用于本人 C++ 学习笔记问答，覆盖编译链接、变量与头文件、指针引用、static 与 ODR、单例、构造析构、多态与智能指针、抽象接口、数组字符串。答案以审核后的笔记为依据；证据不足时说明缺失内容，完全缺少依据时拒答。

资料核验与生成忠实度分开记录，检索到的原文仍需经技术核查。

### 2. 语料统计及预处理

当前可核查库存为 **9 个 Markdown 文件、774 行、25 个 fenced 代码块、原始汉字 7364 个、保守正文汉字 6669 个**。用户已确认笔记为本人原创；计数程序只统计文本，不能验证作者身份。

1500 字验收口径仍待确认：第 5、7 篇原始汉字分别为 1503、1745 个；排除代码和标记等后的正文汉字分别为 1217、1458 个。单篇正文汉字最高 1458，不能宣告单篇门槛已通过。可以计划制作保留九章来源的可追溯合辑，当前不修改或自动补写原文。合辑能否满足作业对“一份内容”的定义须明确，导入副本和格式转换不增加原创正文。

正式报告填入最终采用的计数口径、资料版本及实际处理结果，并交代：

- UTF-8 Markdown 原生导入，以及由同源内容生成的 UTF-8 TXT 格式导入验证；按 `source_id` 去重，两种格式使用同一份资料。
- 清理 HTML 样式时保留正文；完整保留 fenced 代码、缩进、运算符和 C++ 标识符。
- 按标题和段落切片，代码与必要解释共同保留；填入最终 chunk 数量、长度和重叠规则。
- 引用采用原始文件、标题路径与行号；TXT 或合辑的派生位置映射回原始文件。
- 第 1 篇已补齐图片附件，通过 `data/attachment_map.json` 将原嵌入引用关联到 `1图片引用.png`；原文和图片名保持不动。图片可作为附件展示，文本检索仅使用文字与代码，不读取图像语义；说明依赖图意及其他待核段落如何处理，哪些内容已排除出正式金标准。

### 3. 架构图

架构图按以下流程绘制：

> C++ Markdown / 同源 TXT → 解析与来源映射 → 审核、去重和统一切片 → BM25 / 本机 BGE + Chroma → Top-3 证据 → 证据与引用规则 → DeepSeek-flash → Streamlit 回答、证据与耗时展示。

BGE 在本机把文字转换成检索向量，Chroma 保存和查找向量，DeepSeek-flash 通过 API 根据检索片段生成中文回答并保留英文术语。报告区分这三个模块的职责。

### 4. 关键实现

简述运行时切换检索方法、Top-3 展示、可核查引用、仅回答有依据的部分、无依据拒答、凭证读取和成本记录。API 故障单独显示并保留日志，服务故障与资料无答案分别统计。

## 四、第 2 页：实验设置与真实结果

### 1. 固定实验设计

- 正式集为互不重叠的 **10 道有答案题、5 道资料无答案题、5 道跨片段题，共 20 题**，考查笔记支持的概念、机制和适用条件。术语与符号、同义改写和代码语义作为附加诊断标签。
- 评分接受语义等价表述，不强制原示例的类名、函数名、变量名、字符串、初始化数值或具体输出，不要求为概念题另外编写代码。C++ 版本、const 限定、引用绑定与指针指向等语义条件仍须正确；解释可改写，原文引用仍须真实且逐字可核对。
- Q17 考查引用赋值与引用成员构造时的绑定，区分对已绑定对象赋值与完成初次绑定，不限定示例或唯一初始化写法。Q19 考查继承是否足以获得运行时多态、virtual 的动态绑定，以及纯虚接口和抽象类不能直接实例化的关系。陷阱题问资料未覆盖的机制或条件，不以精确实现数值的背诵作为难点。
- 由 AI 起草题目、标准答案、必要证据及评分规则，用户在正式运行前审核，运行后最终核对判分。
- 有答案和跨片段题标注必要原文与文件、章节、行号；无答案题标注范围核查理由，证据集合允许为空，不虚构出处。
- 题目先经资料核验，再锁定金标准；待核技术结论不直接作为标准答案。
- 两组固定资料、切片、Top-3、上下文预算、模型、提示词、参数和评分规则。BGE 模型版本、Chroma 距离度量、BM25 分词方式及阈值写入配置快照。
- 开发题与正式题分离，阈值和提示词仅用开发题调整。运行后改动配置须创建新版本并另行验证。
- 主实验两种方法各运行 20 题，保留 **40 条完整记录**。有余量才复测，复测结果与主实验分开存放。
- API 总预算上限 **20 元人民币**，记录实际 token、价格依据及费用，接近上限时停止追加调用。人工审核与录屏预计 **3–4 小时**，优先完成资料核验、金标准审核及 40 条评分。

### 2. 指标与主结果表

所有“待测”只能在脚本运行、用户审核后填入真实数值。

| 方法 | 答对 /20 | 正确率 | 陷阱硬编 /5 | 陷阱幻觉率 | Top-3 任一证据命中 /15 | 跨片段完整证据覆盖 /5 | 完整回答平均耗时 /s |
|---|---:|---:|---:|---:|---:|---:|---:|
| BM25 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 |
| BGE + Chroma | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 | 待测 |

指标口径：

1. 正确率分母固定为每种方法的 20 题；有答案题须满足预先审核的必要含义与证据要求，语义等价的解释不因命名或措辞不同而失分，无答案题正确拒答算答对。仅回答部分内容、遗漏必要机制或适用条件时，按金标准完整性要求判分。
2. 陷阱幻觉率为 5 道无答案题中，编造资料不支持的实质答案的题数除以 5；同时报告正确拒答数，避免以过度拒答掩盖其他错误。
3. Top-3 任一证据命中的分母为 15 道可回答题，无答案题记 N/A；跨片段完整覆盖另以 5 题为分母检查全部必要证据。
4. 完整回答耗时从提交问题到答案、引用均就绪，报告可完成回答的样本数；API 失败及其耗时另列，不能静默剔除。分开记录检索耗时与生成耗时，一次性建索引和首次加载时间另记。
5. 失败或超时保留在 20 条原始记录中，按预定规则标记任务未完成；重试保留关联记录，不能覆盖原始异常或改变正式题目的分母。

## 五、第 3 页：两段规定分析

### 分析 A：两种检索各适合什么问题，为什么？

**正文至少 200 字。**先给出真实结果，再用题目 ID、检索片段和评分解释差异。围绕 C++ 标识符、`static`、`const`、`delete[]`、中英文术语、同义表达、代码与解释共同出现的情况展开。

分析至少包含一组同题对照，并区分检索未命中、缺少跨片段证据、证据充分但生成出错。检查分词是否破坏符号、切片是否拆开代码与解释、embedding 是否区分相近术语，以及原始笔记的歧义是否影响答案。BM25 在术语匹配上可能有优势、向量检索可能更适合改写，这些只是待验证解释；结果相近或相反时据实分析。

### 分析 B：最失败案例及根因是什么？

**正文至少 200 字。**选择一个实际失败案例，呈现完整证据链：

> 问题与已审核标准答案 → 必要原文（文件、章节、行号）→ 实际 Top-3 → 模型原始回答 → 人工判分 → 根因证据 → 修正方案及代价。

检查来源是否缺失，资料表述是否未经核验，切片是否切断代码，检索是否漏掉必要证据，阈值是否误拒答，模型是否补入外部常识，引用是否存在却不能支持回答。区分资料错误、检索错误、生成错误与评分错误，避免将所有失败归因于模型。

主实验后的修复列为后续改进；声称修复有效须另做验证并标注新配置，不能将修复前后结果混入同一张主表。

### 2. 三项课程反思

- **如何利用 AI 重构代码：**结合实际发生的模块拆分、统一检索接口、来源映射、配置管理或错误处理，说明前后变化及验证方式。
- **评测陷阱：**讨论金标准泄漏、正式集调参、把示例复述当作概念理解、因不同命名误判语义等价答案、原文错误被当成真理、单一命中掩盖跨片段缺证据、过度拒答、模型自评、小样本及失败记录被剔除等实际问题。
- **AI 时代的重要能力：**用本项目实例说明需求拆解、独立技术核验、证据意识、实验设计、错误定位和成本判断的重要性。

### 3. 局限、结论与复现

局限包括笔记覆盖范围有限、部分技术表述待审、附件图意未纳入文本检索、代码语义与文本检索的差距、20 题样本较小、云 API 网络波动。以实测支持的结论收尾，并给出 README、配置版本、`eval/` 和必要官方参考入口。外部技术资料用于核验时，明确其用途；不将其静默加入本人笔记知识库。
