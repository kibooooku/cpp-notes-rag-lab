# C++ 笔记问答项目：AI 辅助开发错误记录

这里只记录本版项目实际发生的问题。课程最终报告至少需要三条真实记录；以下记录保留真实发现及修复证据，报告优先采用与系统行为直接有关的条目。

## E01：资料盘点输出没有显式使用 UTF-8

- 日期：2026-10-19。
- AI 给出的操作：在 Windows 默认编码下直接打印包含完整 Markdown 标题的 JSON，未配置标准输出编码。
- 实际错误：笔记标题含 emoji，终端报告 `UnicodeEncodeError: 'gbk' codec can't encode character '\U0001f48e'`，盘点未完整输出。
- 如何发现：检查真实命令退出码与异常，而非只检查文件能否读取。
- 修正：脚本采用 `sys.stdout.reconfigure(encoding="utf-8")`，明确用 UTF-8 读写，保留原笔记内容。
- 复验证据：`python scripts/audit_materials.py` 退出码0，生成有效 `data/corpus_inventory.json`；9文件、774行、25代码块、6669正文汉字。

## E02：同一补丁对同一路径同时执行删除与新增

- 日期：2026-10-19。
- AI 给出的操作：在一个 apply_patch 补丁中，对同一文件同时使用 Delete File 与 Add File，并与其他文档创建混在同一补丁中。
- 实际错误：工具拒绝补丁，报告 `invalid patch: multiple operations target`，计划的文档未写入。
- 如何发现：检查工具错误并实际核对目标文件是否存在，没有把发出写入请求当作写入成功。
- 修正：独立创建新文档；需要替换的文件使用单一路径操作，或分两次顺序完成删除和新增。
- 复验证据：主项目方案与 README 已通过独立补丁落盘，最终核对文件存在及内容；未修改原始笔记。

## E03：预算账本只验证金额，结构损坏时没有立即停止请求

- 日期：2026-10-19。
- AI 的初版代码：`CostTracker._load` 只验证 `version` 与各项 `held_cny`，未核验请求 ID、状态、预留金额及已结算 usage 的完整性。
- 实际问题：合法 JSON 里缺失 ID、重复 ID、未知状态或未知用量的预留被改为零时，`reserve` 仍可能继续请求，之后在结算/展示才出错；`settle` 对非字典 usage 还会抛出 `AttributeError`。这破坏了“账本无法验证时停止调用”的要求。
- 发现证据：针对自然损坏、异常 usage、并发和引用安全的真实测试，修复前 **11 failed / 12 passed**，不是为了报告人为破坏线上账本。
- 修正：完整核验账本结构、有限非负金额、唯一请求 ID、允许的状态、历史预留下限、已结算 usage；未知 usage 保持完整预留。拒绝时保留坏文件，不重置为零；并发请求在同一文件锁内计算及预留。
- 复验命令：`.venv/Scripts/python.exe -m pytest tests/test_generation_security.py -q --basetemp .cache/security-tests`。
- 实际结果：专项 **23 项通过**；16 个并发客户端未突破测试预算，超时继续占用预留，损坏账本未被覆盖。安全专项与生成/发布测试合跑 **35 passed / 119 subtests passed**，全部是本机与模拟 HTTP，未产生付费调用。

## E04：过宽的依赖范围引入了初始化性能问题

- 日期：2026-10-19。
- AI 初始配置允许宽版本范围，解析出了 Sentence Transformers 5.7.0、Transformers 5.20.1、Torch 2.14.1，未先做最小模型导入验证。
- 实际问题：首次初始化多分钟未完成。faulthandler 的真实堆栈定位到 Transformers 导入 DTensor，继而触发 Torch fake registration、`inspect.getmodule` 和 Windows `ntpath.realpath` 路径遍历。未声称已证明死锁。
- 修正：核对 Sentence Transformers 声明的 `transformers>=4.41,<6` 约束及官方源码，固定可实测工作的 Transformers 4.44.2，保留 Torch，不修改标准库。中间候选 4.57.6 仅经源码检查，未将其写成实测失败。
- 复验：Sentence Transformers 最小导入 25.506 秒完成；完整本机 BGE 与 Chroma 建库 53.723 秒完成，9 文件、64 共享片段、512 维，实际 token 范围 5–479。依赖锁文件保存实测版本，BGE 固定到不可变 commit。

## E05：要求模型复制引文，对不换行空格过于脆弱

- 日期：2026-10-19。
- AI 初始实现：生成 JSON 同时给出证据 ID 和逐字引文，程序严格验证原文子串。
- 实际问题：独立开发集首轮 12 条中，D05 的两种检索均找到正确片段、生成部分回答，但模型把原文 `栈数组\u00a0` 后的不换行空格 U+00A0 改成 U+0020 普通空格，严格校验拒绝了两条结果。原始结果保存于 `eval/runs/dev-01/`，没有改成成功。
- 修正：按最初架构让模型只选择实际证据 ID，由程序提取对应原文件中的完整片段与行号；不让模型重新键入引文。未知 ID 仍拒绝，旧客户端若传入 quote 仍要求完全匹配，不对代码或字符串做宽松空白替换。
- 复验：新增真实 U+00A0 与 `char buffer[8] = {};` 的原文回归测试，确保程序输出与文件原文一致；生成、安全和评测专项 40 项通过。修后真实开发复测单独保存到 `eval/runs/dev-02/`，提示词指纹与初版不同，不能混为一轮正式成绩。
