## 录屏前准备

按 [README](../README.md) 的实际命令启动本机页面。预先完成依赖安装、embedding 下载、两套索引构建和应用预热；这些冷启动耗时单列，不计入“预热后的完整回答延迟”。核对侧栏资料数量、当前方法、模型和可用预算。关闭凭证文件、终端敏感输出及无关窗口，浏览器保持适合阅读中文与代码的缩放比例。

准备一份本地 UTF-8 TXT 导入样例及其来源映射，在录屏前完成第二种格式的实际验收。若样例是 Markdown 的同源导出，展示去重结果，不把两份格式算成两篇原创内容。第一篇的图片附件已关联，当前问答使用文字和代码，不将图片内容当成已经识别的证据。

选定下表两道有答案演示题，并在录屏前核查其来源。若真实 Top-3 没有覆盖必要证据，保留部分回答或拒答并解释，不修改金标准来迁就演示。预算不足或 API 故障时先解决实际问题，不将故障改写成“文档中没有相关信息”。

## 对现场追问的回答

“本机 embedding 是什么？”——把笔记和问题在我的电脑上编码成数字向量，用于查找相近证据；它不负责生成最终回答。Chroma 保存和检索这些向量，DeepSeek API 负责回答。

“为什么检索到了还拒答？”——相近主题不一定包含答案。例如有 `std::string` 的介绍，仍未记录具体实现的 SSO 阈值。Top-3 是候选证据，需要检查能否支撑所问结论。

“笔记写错了怎么办？”——保留原文，单独登记待核位置。回答标明资料待核，不把引用存在当成技术已经核实；未经确认的结论不作为权威金标准。
