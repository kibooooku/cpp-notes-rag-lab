# 评测审核与判分说明

`eval/questions.json` 是 20 题候选金标准：Q01–Q10 有答案、Q11–Q15 无答案、Q16–Q20 跨片段。当前全部 `reviewed: false`，没有正式成绩。`eval/dev_questions.json` 是独立开发集，只调试分词、提示词、部分回答和引用，不代替正式题库，不计入课程指标。题库、金标准及结果都不能进入知识库。

## 运行前审核

用户逐题对照原文确认问题、`gold_answer`、`required_points`、缺失信息和禁用的无依据结论。原笔记疑点见 [资料审核清单](material-review.md)，不要因原文说了某句话就把它当成已经技术核实的结论。

完成索引后运行：

```powershell
python scripts/review_eval.py
```

该命令生成 `eval/evidence_candidates.json`，只计算来源行范围的重叠候选，不批准金标准、不判语义支持。每个证据组的 `sources` 是可接受的替代来源；完整回答必须覆盖全部必要组。用户应阅读候选 chunk 的实际内容，而非只检查行号相交。

本次结构化草稿比最初蓝图收紧了证据设计：Q18 将“裸内存维护风险”“数组传参退化”“vector.size()”拆为三个必要组；Q05/Q16 不把仅含类外定义注释的行当作 C++17 共享存储完整依据；Q17 以实际引用成员及初始化代码作为必要来源；Q19 的输出必须来自代码，不能仅凭多态概念说明。这些调整发生在主实验前，仍全部待用户审核。

跨片段题还要核对：任何一个 chunk 均不能独立回答全部要点；2–3 个 chunk 能给出完整证据。若候选来源范围过宽，先细化行号或题目再审核。自动候选映射不是语义判断，不能用“有两个文件名”代替这个审核。陷阱需重新通读最终去重语料，确认所问关键内容确实缺失。

**只有用户实际完成审核后**才记录批准，例如：

```powershell
python scripts/review_eval.py --approve-ids Q01 Q02 --reviewer "本人姓名" --notes "已核对这两题的答案、原文和最终切片" --confirm-user-review
```

可分批审核，完成全部 20 题后再正式运行。AI 不应自行执行这条批准命令代替用户。批准会记录题目内容、原始资料和切片的哈希；之后改题、改金标准、改原文或重新切片都需要重新审核。该状态是项目内的审核记录，不是身份认证。

## 运行方法

```powershell
# 开发集，可先单独验证 BM25；使用新的空输出目录。
python scripts/run_eval.py --dev --methods bm25 --output eval/runs/dev-bm25-01

# 开发集两方法对照；仍然不产生正式成绩。
python scripts/run_eval.py --dev --output eval/runs/dev-both-01

# 所有金标准审核及证据审核通过后，正式两方法各 20 题。
python scripts/run_eval.py --output eval/runs/formal-01 --seed 20261019
```

正式运行前，脚本阻止未审核金标准和过期快照；不会为了通过而自动标记审核。脚本预热两种检索器，记录冷启动耗时；用固定随机种子打乱 40 个“问题、方法”组合的执行顺序。每题独立调用，不带前题历史；没有评测器层面的自动重试或答案缓存。程序异常、API 失败及暖启动失败均保留记录。每次追加实验需新的输出目录，不能覆盖首轮或选取较好回答拼接。

输出包括完整原始数组 `results_bm25.json`、`results_vector.json`（正式完成后各 20 条）、逐条 `run_log.jsonl`、配置及资料快照 `run_metadata.json`、冷启动 `warmup.json` 和空白 `judgments.csv`。每条原始记录包含问题、方法、真实检索文本与位置、原始回答、引用、状态、usage、异常及耗时。中断时保存的是已完成的部分记录，不能当成完整主实验。

`automatic_source_overlap` 仅便于人工定位候选证据，不是评分。引用存在只能证明引用位置真实；是否支持答案仍须读上下文。成本由服务的项目累计账本控制，开发、正式运行、失败调用和演示共同受 20 元预算限制。

## 人工判分

用支持 UTF-8 CSV 的编辑器打开 `judgments.csv`。逐条阅读原始结果、金标准和 Top-3 实际文本，最终由用户核对。判完填写实际 `reviewer`，再将 `reviewed` 设为 `true`。空白表示未评，不能拿来当 `false`；布尔字段只填 `true`/`false`（兼容 `1`/`0`、`yes`/`no`）。不要修改 run_id、question_id、method 或 category。

| 字段 | 填写规则 |
|---|---|
| `answer_correct` | 全部必要答案要点正确、条件完整、无实质错误且有据，才为 true。部分回答、误拒答、API 错误均为 false；陷阱明确拒绝补全缺失关键结论可为 true。 |
| `hallucinated_trap` | 只填陷阱题：编造资料未支持的所问关键答案为 true，即使外部常识碰巧正确；只复述有据背景并明确缺口为 false。运行错误为 false，但正确性仍为 false。 |
| `top3_any_hit` | 只填 15 道有答案/跨片段题：Top-3 至少一条实际内容支持一个必要证据组为 true。只有名称或行范围相交不够。陷阱留空。 |
| `all_groups_covered` | 只填 5 道跨片段题：Top-3 联合支持全部必要证据组为 true。来源重叠、重复导出或同一事实重复不能冒充补足另一要点。 |
| `citation_supported` | 正文的实质结论由所引原文支持且来源准确为 true。纯拒答没有作实质结论时可为 true；有据背景的部分回答须检查对应引用。API 错误为 false。 |
| `notes` | 说明缺失要点、符号错改、版本遗漏、引用不支持、误拒答或故障。建议逐句指出问题。 |

有答案但没检索到，属于检索失败，不能改为“全文无答案”；资料中没有答案的陷阱，即使模型背出了正确教材知识，也不满足本项目。部分回答可以在有据性上通过，但不能因此判完整答对。

## 汇总口径

```powershell
python scripts/summarize_eval.py eval/runs/formal-01
```

只计算用户 `reviewed=true` 且必填字段齐全的判断。对应完整分母未审完时，`summary.json` 保留已审数量、必要分母，正式比率为 null，`summary.csv` 对应单元格为空；不把漏评当成正确或错误。脚本拒绝开发集生成正式指标、重复或跨运行混合记录及类别被修改的判断。

| 指标 | 固定分母与规则 |
|---|---|
| 答案正确率 | 该方法完整答对数 / 20；陷阱正确拒答计对，运行失败计错。 |
| 陷阱幻觉率 | 该方法 5 道陷阱中硬编关键答案数 / 5。 |
| Top-3 任一命中 | 15 道全文有答案题中，Top-3 命中任一必要证据组数 / 15。 |
| 跨片段完整覆盖 | 5 道跨片段题中，Top-3 覆盖全部必要组数 / 5。 |
| 首次完整回答平均延迟 | 预热后从一次独立提问提交到完整答案和引用就绪的实际外层耗时，平均成功完答样本；拒答也属于完答。API/运行失败单列，报告必须同时给成功样本数及错误数。 |

最后一个指标不是首 token 延迟。冷加载、模型下载和建库另列；失败时间仍保存在原始记录，不能静默丢弃。若存在故障，需同时报告完整主实验尚未全部成功，不只展示成功样本均值。保留原始 40 条及所有错误后，再决定是否追加单独复测；不能用复测替换主实验。

报告仍需两段各至少 200 字的分析、至少三条真实 AI 开发错误、四页以内 PDF 和 3–5 分钟真机录屏。统计脚本不生成虚构观察、自动人工分数或占位成绩。
