```cpp
#include <iostream>
class Entity {
    public:
	    virtual ~Entity() = default;
        virtual std::string getName() {
            return "Entity";
        }
};
class Player : public Entity {
    private:
        std::string m_name;
    public:
        Player(const std::string& name)
            : m_name(name) {
        }
        std::string getName() override {
            return m_name;
        }
};
int main() {
    Entity* e = new Entity();
    std::cout << e->getName() << std::endl;
    Entity* p = new Player("John");
    std::cout << p->getName() << std::endl;
    return 0;
}
```
# 继承 多态 虚函数
- 本例中要实现多态，都使用父类Entity类型的指针，一个指向父类Player，一个指向子类Player
- 在java中，父类变量指向子类就能多态，编译时是静态审查，符号`.`之前的类中有这个方法就能通过编译，在运行阶段调用方法时采用动态绑定，看变量实际指向了什么类，并用那个类的方法，如果是子类的覆写方法，就相当于实现多态了。
- 在cpp中，“父类变量指向子类”这一过程就使用指针来实现，其实更接近本质。默认都是静态绑定，想要实现动态绑定，必须使用virtual关键词，并使用override增强代码可读性。
# 虚析构函数

# 内存回收
> 如果这么写，为什么可以说这两个指针delete与否其实无所谓？
##### 1. 核心原因：进程结束，操作系统会回收一切

在 `main()` 函数执行完毕、程序**退出**时，**操作系统会回收该进程占用的所有内存资源**，包括：
- 栈上的局部变量（自动回收）
- 堆上通过 `new` 分配的内存（即使你没调用 `delete`）
所以，对于这个**只运行几毫秒就结束的简单程序**，不写 `delete` 不会造成任何实质性的问题——内存不会被“泄漏”到其他程序，也不会导致系统资源耗尽。这就是“无所谓”的真实含义。
##### 2. 但在实际开发中，这绝对“有所谓”

如果你是在一个**长期运行的服务**（比如 Web 服务器、游戏主循环）里写这样的代码，那么每一次 `new` 不 `delete` 都会造成**内存泄漏**，最终导致进程内存持续膨胀，直到崩溃。  
所以，“无所谓”**仅限于**你这个一次性执行的小示例。
##### 3. 你的代码还有一个特殊点：没有析构函数

你的类 `Entity` 和 `Player` 都没有自定义析构函数，也没有持有任何动态分配的内部资源（比如文件句柄、网络连接等）。因此，即使你调用了 `delete`，默认析构函数也只会释放对象本身占用的内存，而不会做额外清理。  
这意味着不 `delete` 和 `delete` 在**资源清理**上几乎没有区别（唯一区别是前者让操作系统代为回收，后者手动回收）。这进一步强化了“无所谓”的感觉。

# 智能指针
即使在这个简单程序里不写 `delete` 也能运行，但为了养成好习惯，你应该：
- **手动 `delete`**（并加上虚析构函数确保安全）
- 或者**使用智能指针**（推荐）：
```cpp
int main() {
    std::unique_ptr<Entity> e = std::make_unique<Entity>();
    std::unique_ptr<Entity> p = std::make_unique<Player>("John");
    // 离开作用域时自动释放，绝对安全
}
```
这样既不会泄漏，也避免了手动管理内存的繁琐。

# 初始化列表
### 上例中的分析
`: m_name(name)`
这是**初始化列表**，它直接使用传入的 `name` 来**构造** `m_name`。
- **效果**：相当于执行 `std::string m_name = name;`（直接构造）。
- **重要区别**（和直接在花括号里赋值的区别）：
    - 如果写成 `: m_name(name)`：`m_name` 只会被**构造一次**（拷贝构造）。
    - 如果在花括号里写 `{ m_name = name; }`：`m_name` 会先被**默认构造**（空字符串），然后再被**赋值**（拷贝赋值），多了一次无用的操作。
- **强制要求**：如果 `m_name` 是 `const` 类型、引用类型，或者是没有默认构造函数的类，**必须**用这种初始化列表方式，而不能在花括号里赋值。

### 更复杂的例子
为了让你看得更透彻，我写一个比刚才复杂得多的类——`GameCharacter`（游戏角色）。它包含了**普通类型**、**类类型**、**常量**和**引用**，让你看看初始化列表到底有多强大。

### 完整代码示例

```cpp
#include <iostream>
#include <string>
class GameCharacter {
private:
    // 1. 基本类型
    int m_health;
    float m_speed;
    
    // 2. 类类型（string）
    std::string m_name;
    
    // 3. 常量（必须初始化，且之后不能改）
    const int m_maxHealth;
    
    // 4. 引用（必须初始化，且之后不能换绑）
    std::string& m_nicknameRef;
public:
    // ★ 构造函数：初始化列表用冒号开头，多个初始化用逗号隔开
    GameCharacter(const std::string& name, int health, float speed, 
                  int maxHealth, std::string& nickname)
        : m_name(name),          // 初始化字符串
          m_health(health),      // 初始化整数
          m_speed(speed),        // 初始化浮点数
          m_maxHealth(maxHealth),// ★ 初始化常量（这里赋值，之后不能再改）
          m_nicknameRef(nickname) // ★ 初始化引用（绑定到外部变量）
    {
        // 函数体里面不需要再写任何赋值代码了
        // 如果这里写 m_health = health，就是二次赋值，效率低且对常量/引用不合法
    }
    // 打印函数，方便查看效果
    void printInfo() const {
        std::cout << "Name: " << m_name 
                  << ", Health: " << m_health 
                  << ", Speed: " << m_speed
                  << ", MaxHealth: " << m_maxHealth
                  << ", Nickname: " << m_nicknameRef << std::endl;
    }
};
```

### 调用和使用场景

```cpp

int main() {
    std::string nick = "小飞侠";  // 必须是一个左值变量，才能绑给引用
    // 创建对象时一次性传入所有参数
    GameCharacter player("艾丽莎", 100, 5.5f, 150, nick);
    
    player.printInfo();
    // 输出：Name: 艾丽莎, Health: 100, Speed: 5.5, MaxHealth: 150, Nickname: 小飞侠

    // player.printInfo();       // 引用会跟着变为 "闪电侠"
    return 0;
}
```

### 🚨 这一大串初始化列表的三个核心要点（面试常考）

#### 1. 顺序陷阱（极度重要）

**初始化的顺序不是按你在列表里写的顺序，而是按成员在类中声明的顺序！**

在上面的 `private` 声明中，顺序是 `m_health` -> `m_speed` -> `m_name` -> `m_maxHealth` -> `m_nicknameRef`。即使我把初始化列表写成：

```cpp
: m_nicknameRef(nickname), m_maxHealth(maxHealth), m_health(health) // 故意乱序
```
编译器依然会**严格按照 `private` 里声明的顺序**（先 `m_health`，最后 `m_nicknameRef`）去初始化。如果依赖顺序初始化（比如用 `m_health` 去初始化 `m_maxHealth`），乱序会导致**未定义行为**（垃圾值）。

#### 2. 哪些变量**必须**在初始化列表里初始化？

下面的情况，**绝对不能在函数体 `{}` 里赋值**，只能在初始化列表里写：
- **`const` 成员**（如 `m_maxHealth`）：因为常量定义时必须赋值，不能先定义再赋值。
- **引用成员**（如 `m_nicknameRef`）：引用绑定后不能改绑，必须出生时就绑定好。
- **没有默认构造函数的类类型成员**：如果 `m_name` 是一个没有 `默认构造函数`（即无参构造）的类，那么在函数体 `{}` 里 `m_name = name` 会报错，必须用初始化列表直接构造。
    

#### 3. 为什么用初始化列表比在函数体 `{}` 里赋值好？

对比这两种写法：

- **初始化列表**：`m_name(name)` → 直接调用 **拷贝构造**（1次构造）。
- **函数体赋值**：先执行 `m_name` 的**默认构造**（生成空字符串），再执行 `m_name = name` 的**赋值操作**（2次调用）。  
    对于 `std::string` 这种类，两次调用意味着多了一次内存分配和释放的消耗。**C++ 核心准则：能用初始化列表，绝不在函数体里赋值。**

```cpp
// 给构造函数参数设默认值
```
