# 传统数组
- 数组的本质是连续的数据块，索引的本质是指针操作去访问
- 栈和堆上创建数组的区别
	- 栈上 `int a[10]`
		- 数组名a指向数组首地址
		- 离开作用域会自动释放
	- 堆上 `int *ptr = new int[10]`
		- 指针ptr的内存空间包含指向数组的地址
		- 生命周期可以无限长，需要手动释放
		- 删除操作：`delete[] ptr`
	- 堆上数组“开销大”指的是**额外的内存占用**和**分配时的系统调用**，主要有以下三个层面：
	    1. **分配慢**（系统调用 vs 一条 CPU 指令）。
	    2. **多读一次**（先读指针变量，再读目标数据）。
	    3. **缓存差**（栈连续紧凑，堆可能天南海北）。
	    - （详细解释见本页面最下面的附录）
- 数组一定不能越界（有时甚至不会报错，难以排查）
- 数组大小需要自己维护
	- 没有办法像那种把数组作为实例的语言，直接用a.size获得数组大小
	- c++中，数组大小需要自己维护，`sizeof(a) / sizeof(int)`也是不可靠的！
	- 原因：当数组作为函数参数进行传递时，会自动退化decay为指向首元素的指针
	- 维护数组大小的实际方法可见下例，定义xxxSize
```cpp
#include <iostream>
class Entity {
    public:
        static const int aSize = 5;
        int a[aSize];

        Entity() {
            for (int i = 0; i < aSize; i++) {
                a[i] = 100;
            }
        }

        void printArray() const {
            for (int i = 0; i < aSize; i++) {
                std::cout << a[i] << " ";
            }
        }
};
int main() {
    Entity e;
    e.printArray();

    const int bSize = 10;
    int b[bSize];

    for (int i = 0; i < bSize; i++) {
        b[i] = i;
        std::cout << b[i] << " ";
    }
}
```
# std::array(C++11)
- 优点
	- 会进行边界检查，更安全
	- 会保留数组的大小信息，使用更方便
- 缺点
	- 开销略大一点
- **`std::array<int, 10> a;`**（固定大小，栈上）：它重载了 `size()` 方法，底层编译后和原生数组一样高效，但不会退化。
- **`std::vector<int> v(10);`**（动态大小，堆上）：内部封装了 `size()` 和 `capacity()`，你永远不需要传额外的 `int n` 给函数，直接调用 `v.size()` 即可。
# 附录：为什么堆上数组的开销更大
#### ① 分配与释放的代价（最大的开销）

- **栈（`int a[10]`）**：分配时，编译器只是把栈顶指针（`esp`/`rsp`）向下移动 40 个字节（10 * 4），**一条 CPU 指令**搞定，纳秒级。
- **堆（`new int[10]`）**：需要调用操作系统的堆管理器，遍历空闲链表、处理内存碎片、加锁（多线程环境），甚至可能触发系统调用（`brk` 或 `mmap`）。**开销是栈分配的成百上千倍。**
#### ② 存储指针本身的“额外一跳”（你说的“跳来跳去”其实暗含了这个）

这是你问题里提到的“跳”，但你没意识到这里的**双层寻址**：
- **栈数组 `a`**：`a` 在编译时被替换为**栈底的固定偏移量**（如 `[rbp-40]`）。它不占用额外的存储空间，直接就是地址。
- **堆指针 `ptr`**：`ptr` 本身是一个**局部变量**，存储在栈上（占 8 字节）。它里面存的是堆上的地址。
**对比读取流程：**
- 读 `a[0]`：CPU 直接拿栈基址 + 0，读内存（**1次**内存访问）。
- 读 `ptr[0]`：CPU 先从栈上读取 `ptr` 的值（**第1次**内存访问），拿到堆地址后，再去堆上读取数据（**第2次**内存访问）。
所以，**堆确实比栈多了一次读取指针变量的内存访问**。虽然这点开销在单次访问中微乎其微，但在高频循环里是客观存在的。
#### ③ 内存局部性（Cache 命中率）

- **栈**：内存地址连续且紧挨着当前函数的其他变量，CPU 缓存（Cache）命中率极高。
- **堆**：由管理器分配，地址可能很离散。如果 `ptr` 指向的堆内存和当前栈帧不在一起，CPU 缓存可能得去更慢的 RAM 里取数据，**延迟会高几纳秒到几十纳秒**。
# 字符串
- 本质（C中）：const char* 定义的字符数组
	- 原因：字符串存储在内存的**只读区域**，对其的修改属于**未定义行为**，所以要用const
	- 在底层，`"hello"` 的类型是 **`const char[6]`**（一个长度为 6 的常量字符数组）。
    - 只不过在大多数表达式中（比如赋值给指针时），数组名会**退化**（Decay）为指向首元素的指针，所以成了 `const char*`。
- C++：std::string（需要`#include<string>`）
	- `std::string` 的构造函数会将只读的 `"hello"` **深拷贝**一份，存放到**堆（Heap）**或栈上的可写内存中。
	- 之后你修改 `s[0]`，改的是这份拷贝，而不是原始的只读字面量。
