# 纯虚函数（接口）
- 关键字：`virtual` 和 `= 0`
- 有纯虚函数的类是抽象类，不能被实例化，但可以有指针和引用，指向子类对象
- 例如Entity类中有纯虚函数，不能`new Entity()`但是可以`Entity* ptr`或者`Entity& ptr`
- 下面这段程序的设计思路应该是先确认log()函数的函数体和类，再去设计抽象类（接口）！
```cpp
#include <iostream>

//用纯虚函数实现打印类名

class Printable {
    public:
        virtual ~Printable() = default;
        virtual std::string writeClassName() const = 0;
};
class Entity : public Printable {
    public:
        virtual ~Entity() = default;
        std::string writeClassName() const override {
            return "Entity";
        }
};
class Player : public Entity {
    private:
        std::string m_name;
    public:
        Player(const std::string& name) : m_name(name) {}
        std::string writeClassName() const override {
            return "Player";
        }
};

//注意本程序的设计思路应该是先设计这个函数，再设计接口！

void log(const Printable* obj) {
    std::cout << obj->writeClassName() << std::endl;
}


int main() {
    Entity* e = new Entity();
    Entity* p = new Player("John");

    log(e);
    log(p);

    delete e;
    delete p;

    return 0;
}
```

# const
### 1.成员函数末尾的 `const`（`writeClassName() const`）

这是**常量成员函数**，它紧跟在函数参数列表的右括号 `)` 后面。
**核心含义**：这个函数**承诺**不会修改当前对象的任何成员变量（除非成员变量被声明为 `mutable`）。

### 2. 函数参数中的 `const`（`const Printable* obj`）

这是**指向常量对象的指针**。
**核心含义**：`log` 函数承诺不会通过指针 `obj` 来修改它所指向的对象。
**注意细节**：这里修饰的是指针指向的内容（即 `Printable` 对象），而不是指针本身（指针本身是拷贝进来的，无论如何修改它都不影响外部）。

### 3. 最精妙的地方：两者必须配合使用（这是编译通过的关键！）

如果你的参数写了 `const Printable* obj`，但成员函数没写末尾的 `const`（比如写成 `virtual std::string writeClassName();`），那么编译会**直接报错**！
**原因（权限控制链）**：
- 在 `log` 函数内部，`obj` 被视作“指向常量的指针”。
- C++ 规定：**通过指向常量的指针（或引用），只能调用该类型的常量成员函数**。
- 因为“常量指针”意味着你不能修改对象，而调用一个非 `const` 的成员函数，相当于向编译器承诺“这个函数可能会修改对象”，这就违背了 `const` 指针的约束。
**简单记法**：你不能用一个“不能修改对象”的钥匙（`const` 指针），去开启一个“允许修改对象”的门（非 `const` 成员函数）。必须用“只读钥匙”配“只读门锁”。

# 可见性
- public protected private
- private仅该类及其友元friend可用
- protected在该类及其子类中可用
